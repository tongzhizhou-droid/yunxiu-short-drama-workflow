# 通用用户要求（整理版）

本文件只保存可跨项目复用的长期偏好。剧名、人物名、集数、平台链接、余额、单剧授权和生产状态写入根目录 `项目配置.md` 与对应 `output`，不得放回本文件。用户当次要求优先。

## 平台与授权

- 剧梦统一使用可见的 GPT/Codex 内置浏览器；操作前先显示实际制作页，不使用外部浏览器会话替代。
- 默认自由模式、自动放入资产；每集独立项目，每段独立空白分镜单元。用户当次明确改选时才覆盖。
- 所有提示词使用[权威提示词框架](prompt-framework.md)：先保留四条视觉／人物／运镜基调，再依次写“素材引用、轴线控制、前情提要、人物站位、剧情描述、内心独白音效（原文存在时）、镜头1—N”。这条顺序取代旧版“参考素材必须在正文最前”和旧结构。素材引用逐项编号，每项先放真实 `@` 节点，紧接建议名称、类型、使用镜号、用途和禁用范围；平台现有名称与建议名称不一致时同时保留，文字名称不能冒充真实绑定。“轴线控制”固定写在“前情提要”前，至少明确当前主轴、同框人物的屏幕左右关系、摄影机允许停留的轴线半区和允许换轴的建立方式；单写“保持轴线／不要越轴”不算完成。
- 同一编辑页核对正文、真实素材标签、模型、参考方式、画幅、分辨率、时长、费用与余额。平台能力和价格以当时页面为准。
- 模式、默认参数和保存链接不构成付费授权。生成、重试与增强仅在项目配置明确覆盖的范围内执行，不把单剧授权扩展到其他项目。
- 出现失败先确认任务真实状态和平台反馈，检查提示词、引用和非必要品牌内容；作一次有实质变化的修正后单次重试，不盲目连续扣费。

## 原文、旁白与对白

- 从已有剧本进入时忠实保留主线因果、关系、动机、说话人、顺序和结果；未经要求不重新开发故事或擅自翻译、本地化改写。
- 旁白以完整保留为起点。收到音频后保留原件，按原文逐句核对、切自然气口并实测时长；不删词、不机械变速、不把对白混入旁白。
- 每句旁白须有相关事件、动作、证据或合理主角视点覆盖。画面不足就补有效镜头或合理拆段，不用无关空镜拖时长。
- 生成视频默认无普通叙述旁白、背景音乐和字幕，只含角色现场对白、原文内心独白音效及必要动作／环境声。原文含内心独白时，平台正文必须用“内心独白音效”标签逐字写出当前采用语言的原句，标明角色、原声编号、覆盖镜号和人物不做口型；跨镜连续时全文只发声一次，后续镜头写“连续／完成”，不能重复起句。无内心独白的卡不保留空标题。
- 原文对白保持原语言和完整原话。对白句间紧接，仅保留自然换气与有意义反应；英文对白优先接近每秒 3 词，再按难词、情绪与清晰度复核，不用机械倍速代替表演。
- 人物仍被明显压迫颈部／气管时不说流畅长句；先通过动作解除或减轻压力，再使用与受压程度相符的沙哑、气短和短句。

## 镜头、节奏与表演

- 节奏由事件、语义和情绪变化决定。连续剧情优先放在同一较长生成段内，设计目标通常不少于 15 秒；平台上限、明确换场或必要检查点可缩短，不能为了凑时长拉长停顿。
- 生成段时长不等于单镜时长。同一段内部须随信息、动作和权力变化切换景别与视点；快节奏段无信息镜头原则上不拖过约 3 秒。
- 景别默认少用中景、远景，多用单人近景、过肩近景、反应特写及手部／道具特写。空间关系一旦建立，应尽快切近；只有首次交代站位、距离、行动路线或轴线，完整展示行走、接触、交接、跌倒等动作，或确需重建空间方向时，才短促保留中景／远景，不能为追求近景而破坏动作完整性、站位和轴线。
- 对峙和长对白以说话人近景、越肩反打、听者反应与必要特写推进；空间关系交代清楚后，不长期停在双人中景。
- 情绪用简洁状态、动作、视线、声音和刺激后的反应呈现。情感可以强烈，但必须像正常人；避免机械瞪眼、一直张嘴、夸张定格和无刺激的同步反应。
- 未被原文直接写出的主角／听者反应可以补充，但须服务信息理解、关系变化或情绪落点，不能每句话机械插反应。
- 人物全身目标约八头身，偏高挑模特体态；以实际全身图检查，保留定稿脸，避免头大、肩窄、躯干短和腿短。独立面部特写不参与头身比判断。
- 涉及儿童伤病时通过成人反应或无伤病细节的局部状态间接表现，不直接展示伤口或病容细节。

## 连续性与跨段接法

- 每段设计前预读本段与后续完整事件，核对人物知情、位置、轴线、视线、距离、持物、接触和动作前提；补镜同时检查前后两侧。
- 新交视频必须按实际文件复核版本、时长和尾部，不因同名沿用旧结论。
- 跨生成段的起始状态先按上一段最终采用实片的尾部检查确认；下一段的生成参考则从该实片中选取或截取能清楚表达人物方位、距离、视线、持物、接触、动作阶段的站位关键帧，以及能表达空间布局、背景、光线和轴线的背景关键帧。可使用一张或多张，每张分别限定使用镜号和参考维度；不得直接引用原始尾帧，也不得把尾帧构图照搬为下一段首帧。
- 下一段须接住前段实片已确认的人物方位、距离、视线、景别关系、持物、接触和动作阶段；不得先把人物分开再靠近、突然换边、让已完成动作倒退重演或改变车辆／门／座位关系。同一人物跨段时，下一段首镜须明显改变景别或视角以避免跳帧感，同时维持空间轴线与动作连续。这些起始状态须逐项写进正文并在成片开场复核。
- 现实／回忆默认靠造型、动作、语义和明确的视觉锚点区分；未被要求时不自动添加闪白、泛黄、柔焦、光晕或叠化。

## 资产、记录与验收

- 角色声线采用“添加资产加入确认音频 → 提示词真实 `@` 音频 → 标注对应角色、镜号与仅参考声线用途 → 同页核对”的流程。角色设置里的配音绑定不能代替正文音频引用；仅有名称文字不算完成。只给本卡需要发声且已有确认音色的角色绑定，用户当次指定不绑定的角色除外。细节见[音色资产与正文引用](platform.md#音色资产与正文引用)。

- 人物默认使用已确认造型图，不额外导入独立肖像。场景、道具和音色按实际剧情需要建立映射。
- 默认只交付文字分镜与提示词；只有用户当次明确要求分镜图或新制关键帧时才生成新图片，不因设计、回修或用户提供参考图而自动出图。从已生成的前段实片中截取续段必需的站位／背景连续性关键帧属于续生成准备，不视为额外分镜图交付。
- 不把正反方向场景图、地图证据帧和人物参考混在同一未限定引用中；每项参考只承担标注的镜号和维度，避免镜像、混轴与背景漂移。
- 源件不覆盖。权威稿、逐段计划、旁白表、自审、平台记录和交付记录必须指向同一版本；实质改稿递增版本号。
- 自审默认保留，问题须给出具体段号／镜号、证据、修复和复查结果。文字审查通过不等于实片通过。
- 设计、填写、提交、生成、静帧检查、动态检查、试听、增强和保存分别记录。没有实际检查能力时明确写“未检查”，不能用提示词或单帧截图代替动态结论。
- 本流程默认交付独立视频／音频素材及首尾帧，不自动执行视频拼接、字幕、叠字、配乐混音或发布；旁白切气口与时间校对属于允许的音频预处理。

## 工作流维护

- 只要求整理流程或 Skill 时，只更新模板、规则、索引和校验结果，不恢复旧生产、不上传、不生成、不增强、不扣费。
- 通用规则放在本文件或所属阶段；单集表情、站位、镜号、人物名、替代资产和操作结果只放项目记录。
- 新收到且可能跨项目复用的用户反馈，在未经用户明确为长期偏好、或未跨独立项目／明显不同场景验证前，先记入项目根目录 `经验候选.md`，不自动应用到新项目，也不直接升级到本文件或阶段 Skill。
- 新规则写明适用条件；不要把某一集的临时补救变成所有题材的固定镜序。
