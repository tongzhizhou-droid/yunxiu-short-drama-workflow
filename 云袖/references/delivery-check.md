# 交稿自动检查

此步骤是写提示词、修改、补镜和续写的默认交付步骤，不等待用户提醒。先完成语义自审和回修，再对最终稿运行检查。只做剧情分析时不制造提示词来满足校验。

## 正文边界

每个独立生成段用下面两个HTML注释标明范围，注释不属于平台提示词，渲染阅读时不显示。完整稿的版本、来源、估时和自审信息放在标记外；逐镜正文放在标记内。导出到平台或聊天时只取标记内正文，不重新改写前缀。

```text
<!-- yunxiu-prompt id="C12-01" -->
此处按权威框架写完整四条基调、素材引用、轴线控制、前情提要、人物站位、剧情描述，以及镜头1—N。
原文有内心独白才在剧情描述后加内心独白音效；无则删去该栏目。
<!-- /yunxiu-prompt -->
```

上面是边界示意，不是可交付样稿。段ID采用本项目原段号，不要求改成C12-01。每段镜号从1连续，不必固定镜数。每个镜头标题使用“镜头1：”，可在数字后加时间括号；不要把另一次切镜藏在同一个镜号中。

## 运行

在实际项目根目录调用可用的Python 3解释器，路径按本包位置解析，不硬编码用户名。脚本只用标准库，无需安装依赖。

```powershell
python "云袖/scripts/check_prompt.py" "output/第XX集_分镜稿.md" --framework "云袖/references/prompt-framework.md" --segments C12-01 C12-02 --report "output/第XX集_格式校验.json"
```

把文件名、段ID替换成本次逐段计划的全部交付范围。原文发声清单中含内心独白的段，加 `--os-segments C12-02`，脚本检查该栏目是否存在；没有则不传。文件必须UTF-8。

退出码0才表示结构通过；非0时读取报告中的段ID与问题，自行修复并重跑，不询问是否要修正常规格式问题。规则来源或执行环境缺失时如实说明，只交待核验稿。报告保留稿件与框架SHA-256，正文修改后旧报告失效。

检查范围：每段四条前缀逐字一致，栏目齐全且顺序正确，不重复、不空置，镜号连续，段ID与计划一致，正文没有漏在标记外；指定OS的段具备对应栏目。标为待补的真实资料缺口可以保留，但整栏“待填写”不能冒充正文。

## 内容自审仍须执行

逐项核对原文的行动、对白、旁白及内心独白，不把叙述自动转成画面后漏掉应保留的原声；有标黄等格式约定时读取实际文档格式并确认含义。核对每次发声的角色、完整原句、跨镜仅一次、相关画面覆盖及估时／实测状态。逐镜检查近景与过肩偏好、必要空间建立、具体轴线、动作可见性、情绪刺激、接点、持物与资产用途。新增动作明确记在制作注记中。

自审记录至少写：本次稿件版本、审查段镜范围、原文／声音覆盖证据、具体问题及回修、复查结论、未检查项、格式报告路径和最终稿SHA-256。不同结论分别记录，不能用结构PASS宣布旁白已对齐、素材已绑定或视频已验收。

## 用户明确覆盖规范时

只有用户本次明确要求改变四条基调时，才可传 `--prefix-overrides 文件.json`。文件格式为 `{"source":"用户原话及日期／消息定位", "lines":{"视觉基调":"视觉基调：用户指定的新整行"}}`；仅替换指定整行，其余照旧。把覆盖依据记入自审，不为消除报错自行创建覆盖。

用户明确要求另一套完整输出格式时按其要求交付，记录“用户指定格式例外”；不伪造默认框架PASS。此例外不改变后续任务的云袖默认。
