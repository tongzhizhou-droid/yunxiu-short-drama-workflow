# 云袖工作流

先读[通用用户要求](references/user-requirements.md)、根目录 `项目配置.md`、实际 `input`／`旁白` 和受影响的 `output`，确认剧目、范围、权威版本、真实进度与授权。用户当次要求优先；历史“最新”、模板、链接或默认参数均不构成当次状态或付费授权。

本流程交付独立视频／音频素材、连续性关键帧、验收与归档记录；不拼接整集、剪辑、烧录字幕、叠字、配乐混音或发布。只整理 Skill 时不恢复生产、不改历史稿、不打开平台、不产生费用。

## 路由

| 任务 | 执行 |
|---|---|
| 新制作／补镜／重做 | 1→2→3→4→5→6；补镜同时检查前后两侧 |
| 只写提示词 | 1→2→3→4，不打开平台 |
| 只审稿 | 读原文、当前权威稿、连续性与资产映射后执行4 |
| 只上传资产 | 2→5 |
| 只填已审稿 | 确认1—4的版本后执行5，默认不生成 |
| 只生成／增强／下载 | 核对本项目当前范围授权后执行6 |
| 英文剧本翻译 | 读[翻译流程](references/script-translation.md)；不自动进入制作 |

## 六个阶段

| # | 阶段 | 主要结果 |
|---|---|---|
| 1 | [剧情连续性](skills/yunxiu-story-continuity/SKILL.md) | 原文范围、因果、知情、起止状态与后续前提 |
| 2 | [美术与声音资产](skills/yunxiu-assets/SKILL.md) | 可读输入、稳定资产键、缺项与适用范围 |
| 3 | [导演与分段](skills/yunxiu-director/SKILL.md) | 唯一权威分镜稿、声画时间与逐段计划 |
| 4 | [分镜自审](skills/yunxiu-review/SKILL.md) | 带镜号证据的问题、修正、复查与放行范围 |
| 5 | [剧梦填写](skills/yunxiu-platform/SKILL.md) | 真实卡ID、正文、真实 `@`、时长及同页核对 |
| 6 | [生成与交付](skills/yunxiu-delivery/SKILL.md) | 授权内生成、实片验收、关键帧、增强／下载与归档 |

## 全程不可变条件

- 忠实保留原文主线因果、关系、动机、说话人、顺序和结果；未经要求不重写故事、翻译或本地化。
- 旁白以完整保留为起点；有音频时先按原文切自然气口并实测，用户明确要求精简时才删减。生成视频默认无普通叙述旁白、背景音乐和字幕；原文明确的内心独白须在正文逐字写出当前采用语言的原句，统一标注“内心独白音效”，注明角色、覆盖镜号与不做口型，不得只写OS编号或改写概意。
- 节奏由信息、正常语速、完整动作与情绪变化决定，不为固定秒数拉长等待或截断内容。
- 平台生成正文统一使用[权威提示词框架](references/prompt-framework.md)：四条基调后依次写“素材引用、轴线控制、前情提要、人物站位、剧情描述、内心独白音效（原文存在时）、镜头1—N”，不沿用旧结构。轴线控制须落实到屏幕方向和机位半区，不能用空泛的“不越轴”代替；没有内心独白的卡删除该空栏目。
- 跨段先用前段最终采用实片的尾部确认状态，再从该实片选取站位／背景关键帧分维度引用；不直接引用原始尾帧。下一段换景别或视角，但不跳轴、不倒退动作。
- 默认保留自审。设计、填写、提交、生成、静帧检查、动态检查、试听、增强和保存分开记录；文字或截图不等于实片通过。
- 剧梦使用可见内置浏览器、自由模式、自动资产、每集独立项目、每段独立空白单元；当次明确变更优先。只以当前页面判断模型、时长、参考限制、费用和余额。
- 未有当前项目、剧集、操作、次数与费用范围的明确授权，不点击生成、重试、增强或其他付费动作。状态不明先查队列；失败须有实质修正才能在授权内单次重试。

## 维护

通用偏好写入 `references/user-requirements.md`，阶段方法写入对应 Skill，项目事实只留在项目记录。未证实可跨项目复用的反馈先写入根目录 `经验候选.md`；只在用户明确长期意图，或至少两个独立项目／明显不同场景重复成立后升级。修改后检查相对链接、上下游冲突和模板；规则维护不自动触发历史改稿或生产。

## 反馈回修与续做版本

用户反馈、补镜、续做或版本冲突时读取[反馈落实与版本接续](references/feedback-loop.md)，核对根目录 output/当前状态.md；分别记录稿件、平台正文与视频版本。

## 默认触发与执行责任

用户说“写提示词”“做分镜”“按这个剧本写”“修改这段”“继续下一段”，在已建立的剧本制作任务中均自动进入云袖流程，不要求再次点名Skill或提醒格式。新稿、初稿、局部回修、续写和聊天中直接展示的正式提示词都遵守同一正文框架，不能以“初稿”为由降级成自由格式。

先读本包云袖入口、通用要求、权威提示词框架、导演与自审Skill，再完成对应阶段。基础拆镜／叙事技能仅补充方法，不能覆盖云袖正文结构；发现全局同名Skill或旧模板不同，以本项目云袖规则为默认。用户当次明确指定其他格式时遵从，并记录该次例外，不伪称通过默认云袖校验。

“只拆解／分析”只做分析；“只审稿”只审；翻译、总结、保存资料或等待补件不自动扩成创作。用户没有提供资产但要求纯文字稿时，参考标待补，继续可完成的文字设计；不得编造已核验、已绑定或平台可生成。原文不可读、关键剧情歧义或续实片缺失时只暂停受影响部分。

## 交稿必须走两道检查

1. 每个独立生成段从权威框架复制四条基调，逐项填写后续栏目；每段单独具有完整框架，不能全文只写一次前缀。先保存本次最终正文，聊天展示稿也由这份文件导出。
2. 按[交稿自动检查](references/delivery-check.md)运行本包Python校验器。范围必须与逐段计划的交付段ID一致；初稿、修改稿也检查。失败先回修再运行，不把失败文件作为符合云袖规范的成稿交付。
3. 执行云袖自审：核对原文／旁白覆盖、说话人、轴线、动作、节奏、表演、资产用途与前后连续性，写明镜号证据和未检查项。结构PASS不能代替这一步。
4. 自审改动正文后重新运行校验；最终报告中的稿件SHA-256必须对应实际交付文件。简短汇报“格式校验结果／内容自审结果／待核验项”，不用用户再问是否按Skill执行。

校验器只是本地检查工具，不会后台监听。助手在交稿步骤主动运行它；无执行工具时逐项人工检查并明确“脚本未运行”，不能声称机器检查通过。已有有效授权不重复确认，制作范围与费用权限不因默认调用而扩大。
